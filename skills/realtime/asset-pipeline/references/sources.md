# Sources and checks

## Code-only mode

In `code-only` mode (`"assetMode": "code-only"` in `app.json`) run no asset script at all: geometry, textures, shaders and sound are made by the app's code, and `verify` fails any asset file.

## Source order

1. Models: a pack first (`pnpm asset pack`, Kenney and Quaternius as GLB), one family per game where it covers the roles, the family the art bible names. Pick against the game's theme and setting first: run `pack sheet` with the theme as the query and choose from the thumbnails, not the names, and only then check triangles and size.
2. Poly Haven or ambientCG for textures, HDRIs and realistic props.
3. Code-made assets (procedural geometry, canvas or shader textures, synthesized sound) cover only what no pack or library has, such as a pattern, a particle sprite or a simple prop.

Nothing is generated by a model, and 2D cutouts never stand in for a 3D model.

## Model checks and clips

`pack fetch` already normalises and checks a model and prints its animation clips; `check-glb` prints the clips too. A model passes its role with the pivot at bottom-centre, lit materials and the triangle count inside budget. Write each clip that fits a state (idle, walk, attack, hit) into the app's animation code, or note why one is unused. A model that moves without playing its clips is a defect.
