# Attempts mode

Used when `--attempts` is 2 or 3. The session is the orchestrator; attempts are background subagents.

1. **Plan.** `scripts/plan-attempts.sh --lab <lab> --app <app> --attempts <n> [--run-id <id>]`. Done when it prints one line per attempt and exits 0 (it refuses an existing branch or path; pick another `--run-id` then).
2. **Create.** For each plan line: `git worktree add -b <branch> <worktree> HEAD`, then `pnpm install --frozen-lockfile --offline` there. Scaffold once (steps 1 and 3 of the skill) in the first worktree, then copy the app folder and brief into the others so every attempt starts from the same commit content. Done when every worktree has the app and `pnpm check <app>` passes.
3. **Logs.** In each worktree: `scripts/start-run.sh --app-dir <worktree>/apps/<category>/<app> --budget <budget> --mode <mode> --title <title> --attempts <n> --no-marker`. Commit `LOOP.md` and `.gitignore`. Done when each log says `Attempts: <n>` and `Status: running`.
4. **Spawn.** One background subagent per attempt, all in one message, all with the same brief: the skill's steps 5 and 6 (direction loop, cut and keep), the worktree path, the app folder, the budget, the overnight safety rules, and "report when you stop, with the last cycle line". Attempts never see each other's branches.
5. **Outer loop.** Each report: read that attempt's `LOOP.md`. If its budget is not spent and the log is not `Status: done`, send that attempt the next unchecked direction (or, when none is left, a review cycle) with SendMessage and print one status line. When the budget is spent, mark the attempt finished. Do not poll; act on reports. Budget is read from the log header (minutes: the end time; cycles: the count of `## Cycles` lines).
6. **Hand-off per attempt.** Set `Status: done` in its log, `pnpm check <app>` in its worktree, commit.
7. **Stacked video.** From any attempt worktree: `pnpm record <path-a> <path-b> [<path-c>]` (app folders in letter order). It writes each `play.mp4` and `.verify/record-stack/stacked.mp4`. Send the stacked video with SendUserFile, with one line per attempt (letter, branch, last cycle line, open items).
8. **Pick.** Review mode: ask which attempt to continue and wait. Overnight mode: do not wait for an answer; send the video and the lines, say the pick waits for morning, and stop. Never choose for the user.
9. **Continue.** From the picked attempt alone: start its log again with `start-run.sh` (marker on, `--force`, `--attempts 1`), then run the skill's steps 5 to 8 there. Leave the other worktrees and branches untouched and name them in the summary so the user can delete them.
