# Game Design

A design handbook by topic: short rules with numbers and checks, read one file at a time.

## What It Does

| Topic | Rules file covers |
| --- | --- |
| loop | the core loop, goals at three time scales, choices, replay |
| difficulty | curve, tension and relax, retry cost, waves and bosses |
| onboarding | title to play, the first minute, teaching by doing, hints |
| play-field | player never covered, danger readable, telegraphs, banner spots |
| ui-ux | menus, focus, HUD layout, pause and game-over screens |
| copy | labels, numbers over adjectives, captions, text length |
| feel | input response, hit-stop, shake, easing, feedback per event |
| sound | music form and adaptive layers, effects, mix |
| accessibility | flashes, shake and motion, colour, remapping, settings |

Each topic has a rules file (about 450 words) and a detail file with examples, a numbers table and sources. Only the rules file is read by default.

## Usage

```text
Players say the boss fight feels unfair, what do I change?
Is this HUD too busy?
Write the game-over screen text and its buttons
Design the first minute for someone who has never played
The wave banner keeps covering my ship
What accessibility options should this game ship with?
Review this build and list what to fix before the next cycle
```

## FAQ

- Does it set the look? No. Style comes from the brief; rules cover clarity, fairness and feedback only.
- What does `[house]` mean? A rule or number of ours, set by playtest rather than a source.
- Can a rule be broken? Yes, when its "Break when" applies; only player-covered and danger-unreadable block a run.
